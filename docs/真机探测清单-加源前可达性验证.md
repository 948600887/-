# 加源前真机可达性探测清单

> **关联决策**：阶段 0/1 已落实「数据陈旧透明化 + 同步流程统一」，但「增加数据源」按 2026-11-06 拍板**暂缓**——卡在「国内可达性未真机验证」。
> **本清单给梦瑶在安卓真机上逐项验证候选新源是否可达**。只有探测达标的源才进入「加源」实现；不可达的源一律搁置并记原因，**绝不硬接**（否则会拖慢同步、甚至触发熔断误伤现有源）。

## 为什么必须真机
- 本机（开发机）无 `adb`、无真机，连的是另一条网络，探测结果**不代表手机网络出口**。
- 国内对币安 / 部分境外汇率 API 存在 DNS 污染、TLS 拦截或地区封锁（如 `api.binance.com` 部分地区回 451），**换 IP 无效、靠连通层失败判断不了**。现有币安行情已绕到 `data-api.binance.vision` 镜像，正说明可达性是硬约束。
- 可达性 = **DNS 解析成功 + TCP 443 可建连 + HTTPS 返回 2xx + 响应是有效 JSON + 延迟可接受**，三者缺一不可；纯靠 Ping 或桌面浏览器打开不算数。

## 前置条件
- 一台能联网的安卓真机（当前常用网络：家 WiFi / 蜂窝数据，二选一，**记录用的是哪种**）。
- 装了 **Termux**（或任何能跑 `curl` 的终端）；iOS 不可用。
- 不需要 root，不需要 adb。
- 候选源全部选**免 API Key** 的公开端点，探测命令里**不要填任何密钥**。

## 探测方法（三层）
在 Termux 里逐条执行，记录每行输出。

1. **DNS 解析**（看能否解析出真实公网 IP，且不是 `127.0.0.1` / `0.0.0.0` 之类）
   ```bash
   getent hosts api.bybit.com || nslookup api.bybit.com
   ```
2. **TCP 443 连通**（看能否建连，3 秒超时）
   ```bash
   curl -sS -o /dev/null -w "tcp=%{http_code} time=%{time_total}\n" --connect-timeout 3 https://api.bybit.com/
   ```
3. **HTTPS 业务端点**（看返回形态 + 延迟，10 秒超时）
   ```bash
   curl -sS --connect-timeout 5 --max-time 10 -w "\nhttp=%{http_code} time=%{time_total}\n" "https://api.bybit.com/v5/market/tickers?category=spot&symbol=BTCUSDT"
   ```

**判定**：三层全过 + 返回是合理 JSON（不是 HTML 错误页、不是空）+ 单次延迟 < ~3s（行情/汇率对延迟敏感），才算「可达」。

## 判定标准（达标才进入实现）
- DNS 解析到一个真实公网 IP（非 `0.0.0.0` / `127.0.0.1` / `::1`）。
- `curl` 三层：HTTP 状态码 2xx；响应体是合法 JSON（首字符 `{` 或 `[`，非 HTML `<`）。
- 业务端点单次延迟 `time_total` ≤ 3s（行情/汇率对同步耗时敏感）。
- **至少在不同时段测 2 次**（避开临时抖动）：建议连测两天或隔几小时。

## 结论如何驱动「加源」决策
- **候选加密源（Bybit/OKX）任一可达** → 进入实现：在 `SourceRegistry` 注册第二加密源（已留 `register`/`fallbackFor` 门），接 `SourceIds` 常量，先只做「币安镜像失败时的降级源」，跑真机一轮验证不误熔后再默认并联。
- **候选汇率源任一可达** → 给 `ExchangeRateManager` 增加第二 `RateSource` 做降级（P2）。
- **全部不可达** → 维持现状（币安镜像 + 新浪汇率单源），**不硬接**；在 `docs/PROJECT_MEMORY.md`「仍未解决」补一条「XX 源国内不可达，已验证于 YYYY-MM-DD」。

## 与门禁的关系
- A7/A8/A9 不挡「加源」本身；但加源改动（新增源适配器、改 `SourceRegistry`/`ExchangeRateManager`）必须过 `bash tools/check_gate.sh`（含 A9 的「source 字段必须走 SourceIds」——新源标识要进 `SourceIds`，不能硬编码字面量）。
- 加源后必须真机跑一轮同步，确认：新源只在失败时启用、不拉高整体延迟、不触发 `BinanceHostGate` 误熔。

## 注意事项
- **网络环境决定一切**：在家 WiFi 通不代表蜂窝通，反之亦然。记录用的是哪种，必要时两种都测。
- 探测命令**不要填任何 API Key / Secret**；候选源都选免 key 端点。
- 若 `curl` 报 `SSL certificate problem`，说明 TLS 被中间人拦截（某些公共 WiFi），换网络再测，**不要在 App 里关证书校验**。
- 不要因为「桌面浏览器能开」就判定可达——桌面网络 ≠ 手机网络出口。
